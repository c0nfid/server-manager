# Server Manager (Android)

Android-приложение для управления Linux-серверами по SSH: хранение доступов,
автоматическая настройка входа по ключу, встроенный терминал, файловый менеджер
SFTP, мониторинг, определение местоположения и управление скриптом
[PortBind](docs/portbind/README.md) (проброс портов через nftables).

## Возможности

| Раздел | Что умеет |
|---|---|
| Серверы | Добавление/редактирование: имя, IP/домен, порт, пользователь, пароль, способ входа, заметки. Поиск, проверка доступности порта SSH и задержки. |
| Безопасность | Данные хранятся в файле, зашифрованном AES-256-GCM ключом Android Keystore. Ключ хоста запоминается при первом подключении (TOFU) и проверяется **до** отправки пароля; при смене показываются оба отпечатка. |
| SSH-ключи | Генерация ECDSA P-256/P-521 и RSA-4096, импорт OpenSSH/PEM/PuTTY (в т.ч. Ed25519 и зашифрованных), копирование и отправка публичного ключа. |
| Автонастройка ключа | Вход по паролю → запись ключа в `~/.ssh/authorized_keys` (права 700/600, без дублей, SELinux restorecon) → проверка входа **только** по ключу → переключение сервера на ключ. |
| Терминал | Встроенный эмулятор xterm-256color: цвета (16/256/TrueColor), альтернативный экран (vim, htop, mc, nano), прокрутка истории, масштаб щипком, панель Esc/Ctrl/Alt/Tab/стрелки/F1–F12, вставка (bracketed paste), копирование экрана. |
| SFTP | Навигация, скрытые файлы, загрузка/скачивание через системный выбор файлов с прогрессом и отменой, создание каталогов, переименование, chmod, рекурсивное удаление, встроенный редактор текстовых файлов до 1 МБ. |
| Мониторинг | CPU (с графиком), RAM/Swap, диски, сетевой трафик, load average, аптайм, ОС/ядро/процессор, топ процессов. Интервал 2–30 с, опрос только пока экран открыт. |
| Местоположение | Страна (флаг), город, регион, провайдер, часовой пояс, координаты и открытие на карте. Источники: ipwho.is, ipinfo.io. Для серверов за NAT/VPN — запрос внешнего IP с самого сервера. |
| PortBind | Установка/обновление скрипта (с проверкой SHA-256), установка зависимостей (apt/dnf/yum/apk/pacman/zypper), список правил (`list --tsv`), добавление/изменение/удаление, `refresh`, `apply`, `reset` с подтверждением, таблица в ядре, автозапуск через systemd, расписание `refresh` в cron с logrotate, резервные копии (просмотр, восстановление, очистка), журнал операций с расшифровкой кодов возврата. |
| Перенос | Экспорт всех серверов и ключей в файл `.smbak`, зашифрованный паролем (PBKDF2-SHA256 + AES-256-GCM); сохранение или «Поделиться»; импорт с объединением или полной заменой. |

## Сборка через GitHub Actions

Локально собирать ничего не нужно: workflow `.github/workflows/android-build.yml`
запускается при push в `main`/`master`, при pull request, по тегу `v*` и вручную
(Actions → Android Build → Run workflow).

1. Создайте репозиторий на GitHub и отправьте проект:
   ```bash
   git init
   git add .
   git commit -m "Server Manager"
   git branch -M main
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```
2. Откройте вкладку **Actions** и дождитесь завершения сборки.
3. Скачайте артефакт:
   - `server-manager-release-N` — основная версия (`com.srvmanager.app`), минифицирована R8;
   - `server-manager-debug-N` — отладочная (`com.srvmanager.app.debug`), ставится рядом с основной.
4. Для публикации релиза создайте тег: `git tag v1.0.0 && git push origin v1.0.0` —
   APK будет прикреплён к GitHub Release.

### Постоянная подпись (рекомендуется)

Без настройки подписи каждый запуск CI подписывает APK новым временным ключом,
и Android не даст установить новую сборку поверх старой (придётся удалять
приложение — перед этим сделайте экспорт данных). Чтобы обновления ставились
поверх, один раз создайте ключ и добавьте его в секреты репозитория:

```bash
keytool -genkeypair -v -keystore release.jks -alias servermanager \
  -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 release.jks > release.jks.b64
```

**Settings → Secrets and variables → Actions → New repository secret:**

| Секрет | Значение |
|---|---|
| `SIGNING_KEYSTORE_BASE64` | содержимое `release.jks.b64` |
| `SIGNING_STORE_PASSWORD` | пароль хранилища |
| `SIGNING_KEY_ALIAS` | `servermanager` |
| `SIGNING_KEY_PASSWORD` | пароль ключа |

Сохраните `release.jks` в надёжном месте и не коммитьте его (он в `.gitignore`).

## Использование

1. **Добавьте сервер**: IP или домен, порт, пользователь и пароль. Кнопка
   «Проверить подключение» сразу проверит доступ и запомнит ключ хоста.
2. **Настройте вход по ключу** на странице сервера: приложение создаст ключ,
   установит его и проверит. Пароль лучше оставить — он нужен для `sudo`.
3. **PortBind**: на странице сервера → PortBind → «Установить», затем при
   необходимости «Зависимости». Дальше — «Бинд порта», автозапуск и расписание.
   Для не-root пользователя нужен `sudo`; пароль передаётся через stdin
   (`sudo -S`), а не в командной строке.
4. **Перенос на другое устройство**: значок ⇅ в списке серверов → экспорт с
   паролем → импорт на новом устройстве.

## Как приложение выполняет команды на сервере

Скрипты из `app/src/main/assets/scripts/` передаются на сервер в base64 и
запускаются как `sh -c 'eval "$(echo … | base64 -d)" </dev/null'`. Это работает
при любом login shell (bash, zsh, fish), не требует временных файлов и исключает
внедрение команд: пользовательские значения (порты, домены, ключи) проверяются
и экранируются, а аргументы `portbind` передаются по отдельности.
Изменяющие операции PortBind не прерываются при уходе с экрана, чтобы скрипт
успел выполнить откат при ошибке.

## Структура проекта

```
app/src/main/
├── assets/
│   ├── portbind/portbind.sh        скрипт PortBind, устанавливаемый на сервер
│   └── scripts/                    серверные скрипты (мониторинг, установка, cron, бэкапы…)
└── java/com/srvmanager/app/
    ├── data/       модели, шифрованное хранилище, экспорт/импорт
    ├── ssh/        SSH-сессии (JSch), TOFU, sudo, ключи, автонастройка
    ├── terminal/   эмулятор терминала, View, SSH-сессия с PTY
    ├── portbind/   клиент CLI portbind, проверка аргументов
    ├── monitor/    разбор метрик
    ├── geo/        геолокация
    └── ui/         экраны Jetpack Compose
docs/portbind/      документация PortBind (README, INTEGRATION)
```

Чтобы обновить PortBind, замените `app/src/main/assets/portbind/portbind.sh`:
версия берётся из строки `--version` скрипта, и приложение предложит обновление
на серверах со старой версией.

## Технологии

Kotlin 2.0, Jetpack Compose (Material 3), Navigation Compose, kotlinx.serialization,
[JSch (mwiede)](https://github.com/mwiede/jsch) + BouncyCastle, AGP 8.7, Gradle 8.10,
minSdk 26 (Android 8.0), targetSdk 35.

## Ограничения

- Генерация Ed25519 недоступна (JSch не умеет сохранять такие ключи), импорт Ed25519 работает.
- Терминал — одна сессия на сервер; выделение текста пальцем заменено копированием экрана/всего вывода.
- Расписание `refresh` использует `/etc/cron.d`; busybox-cron (Alpine) его не читает.
- Сессии SSH не держатся в фоне: при выгрузке приложения системой соединения закрываются.
