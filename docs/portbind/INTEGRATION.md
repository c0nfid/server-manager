# Интеграция portbind 1.0.0 в другие системы

## Назначение и границы компонента

`portbind` — привилегированный CLI-компонент управления IPv4 NAT на одном
Linux-хосте. Он принимает команды от оркестратора, панели управления,
инсталлятора или планировщика. Домен выходной ноды хранится как имя и
разрешённый IPv4; nftables получает числовые адреса.

Компонент не является DNS-прокси, HTTP reverse proxy, балансировщиком или
демоном. Он не настраивает DNS-записи, сетевые интерфейсы, TLS, policy routing
или разрешающие правила firewall. Удалённая нода должна быть достижима
по обычному маршруту сервера.

## Модель данных

Ключ записи — **входной порт**. Ключ глобален для управляемой таблицы,
не зависит от протокола или входного адреса. Значение — входной адрес,
одна выходная нода с одним портом и набор протоколов. Для `both` создаются
два NAT-правила, но в конфигурации это одна запись.

| Поле TSV | Тип | Значение |
|---|---|---|
| 1: in_port | целое 1–65535 | уникальный ключ |
| 2: protocol | tcp / udp / both | разрешённые протоколы |
| 3: bind_host | IPv4 / домен / * | исходное входное имя |
| 4: bind_ipv4 | IPv4 / * | текущий адрес сопоставления |
| 5: target_host | IPv4 / домен | исходное имя выходной ноды |
| 6: target_ipv4 | IPv4 | текущий выходной адрес |
| 7: target_port | целое 1–65535 | выходной порт |

Состояние хранится в `/var/lib/portbind/rules.tsv`. Формат: UTF-8/ASCII,
табуляции, LF, без заголовка; одна запись на строку. Домены нормализуются в
нижний регистр без завершающей точки, порты — без ведущих нулей. IPv4 с
ведущими нулями в октетах отклоняется. Пробелы, управляющие символы,
URL и IPv6 в полях не допускаются. IDN должен приходить в punycode.
Пустой вывод означает отсутствие записей.

Порядок строк не является частью API. `add` сортирует по входному порту.
Отдельно сохраняются имя и IP, поэтому изменение DNS не теряет имя ноды.

## CLI-контракт

| Команда | Действие | Особенности |
|---|---|---|
| `add IN HOST OUT [PROTO] [BIND]` | создать запись и применить | PROTO=both, BIND=* по умолчанию; повторный IN — ошибка |
| `list` | человекочитаемая таблица | не предназначена для парсинга |
| `list --tsv` | машинный снимок записей | только строки TSV в stdout, без заголовка |
| `refresh [DOMAIN]` | обновить DNS и применить изменения | без аргумента — все домены входа/выхода |
| `delete IN` | удалить запись и применить | отсутствующий порт — ошибка |
| `reset --yes` | очистить собственные записи | обязательный флаг; другие таблицы не сбрасываются |
| `apply` | применить сохранённый снимок | DNS не запрашивается; для старта и восстановления после reload |
| `help`, `--help`, `-h` | справка | root не требуется |
| `--version` | версия | root не требуется |

Без аргументов запускается меню из 5 пунктов, требующее терминал на stdin.
Для автоматизации всегда передавайте команду. `list` и `list --tsv` также
требуют root: это закрытые данные конфигурации. Проверка версии:
`/usr/local/sbin/portbind --version`.

| Код | Семантика для оркестратора |
|---|---|
| 0 | успех, включая refresh без изменений |
| 1 | неверные аргументы/конфигурация, конфликт, ошибка DNS при add, отсутствующая зависимость, ошибка nft/sysctl или ожидания lock |
| 2 | refresh: один или несколько доменов не разрешились; успешные обновления могли быть применены |
| 130 / 143 | получен SIGINT / SIGTERM или SIGHUP; выполняется попытка отката |
| прочий ненулевой | ошибка внешней утилиты; считать операцию неуспешной и проверить состояние |

Коды внешних утилит могут передаваться без преобразования в `1`, например
при ошибке резервирования. `2` в контексте `refresh` обычно означает
частичный сбой DNS; журнал обязательно сохраняйте для уточнения причины.
Не классифицируйте ошибку только по русскому тексту сообщения: текст может
измениться. Об успешном DNS-обновлении судите по коду и новому TSV-снимку.

Информационные сообщения операций идут в stdout, ошибки и путь резервной
копии — в stderr. Исключение для машинного интерфейса: `list --tsv`
на успехе выводит только данные. Соединение потоков допустимо для логов,
но при парсинге TSV держите stdout и stderr раздельно.

## Вызов из приложения или скрипта

Вызывайте исполняемый файл как отдельный процесс. Не подключайте его через
`source`: файл меняет shell options и запускает main. Передавайте аргументы
массивом/отдельными параметрами, без `eval` и без построения shell-команды
из пользовательского ввода. Например, для root-процесса на Python:

```python
import subprocess

result = subprocess.run(
    ["/usr/local/sbin/portbind", "add", "8080", "node.example.net", "443", "tcp"],
    capture_output=True,
    text=True,
    check=False,
)
if result.returncode:
    raise RuntimeError(result.stderr or result.stdout)
```

Чтение данных без разбора таблицы:

```bash
snapshot=$(/usr/local/sbin/portbind list --tsv) || exit "$?"
while IFS=$'\t' read -r in_port proto bind_host bind_ip target_host target_ip target_port; do
    [[ -n $in_port ]] || continue
    printf '%s/%s -> %s:%s\n' "$in_port" "$proto" "$target_ip" "$target_port"
done <<< "$snapshot"
```

`list` показывает сохранённую желаемую конфигурацию, не проверяет, что
другой администратор не удалил/заменил правила в ядре. Проверка ядра:
`nft list table ip portbind`. Проверка поведения — соединение с внешнего
клиента к входному адресу и порту. Успех CLI подтверждает настройку, а не
доступность приложения на выходной ноде.

## Привилегии и владение

Все изменяющие команды запускаются от root с доступом к сетевому namespace
целевого сервера. Скрипт устанавливается в `/usr/local/sbin/portbind`,
владелец root; непривилегированный пользователь не должен иметь право
менять сам файл, каталог установки или состояние.

Веб-панель не должна передавать произвольную root shell-команду. Организуйте
аутентифицированный локальный сервис или очередь заданий с проверкой
аргументов и авторизацией владельца портов. Не выдавайте произвольным
пользователям `sudo portbind`: `reset` и доступ к адресам позволяют влиять
на конфигурацию сервера.

Переменная `PORTBIND_STATE_DIR` меняет каталог состояния. Используйте
абсолютный root-owned каталог с правами 700, файлы — 600. Для одинакового
состояния переменная должна совпадать в ручном запуске, cron и сервисе.
Имя таблицы остаётся `ip portbind`, поэтому переменная не создаёт независимый
экземпляр. Один сетевой namespace — один владелец таблицы portbind.

## Блокировки и транзакции

Операции, включая list, берут exclusive flock на `<STATE>/lock`, ждут до
30 секунд. После выхода процесса lock освобождается; сам файл lock
не удаляется. Нельзя удалять/подменять lock-файл во время работы.
Меню не держит lock между командами.

Блокировка координирует только экземпляры portbind с одинаковым каталогом
состояния. Она не блокирует nft, другие firewall-менеджеры или прямую запись
в TSV. В оркестраторе назначьте одного владельца правил и согласуйте
firewall reload с `apply`.

Последовательность изменения: валидация → резервная копия → построение
полной собственной таблицы → `nft -c` → включение forwarding для непустой
конфигурации → атомарное `nft -f` → замена файла TSV через rename.
Обычная ошибка после начала изменения вызывает попытку отката. Полной
транзакции между ядром и диском нет; SIGKILL/потеря питания может оставить
их разными. При восстановлении вызовите `apply`, либо сначала верните
выбранный резервный TSV, затем `apply`.

`add` и `delete` не идемпотентны: повторный add/delete возвращает ошибку.
`refresh` без изменений идемпотентен и не создаёт backup. `apply` и `reset`
повторно создают backup и пересобирают таблицу. Набор delete+add не является
одной транзакцией: между командами порт временно не перенаправляется,
и возможен конкурентный вызов. Для такого изменения оркестратор должен
согласовать операции; атомарного update/bulk API в версии 1.0.0 нет.

## DNS, cron и таймауты

Публичный крючок — `portbind refresh [DOMAIN]`. Он не интерактивен.
Выполняйте от root по расписанию; пример cron есть в README.
DNS TTL автоматически не планирует обновление: интервал задаёт ваша система.

Предел одного lookup — 15 секунд. При refresh каждый уникальный домен
запрашивается один раз. Верхняя оценка времени только DNS: 15 × число
доменов секунд, дополнительно до 30 секунд ожидания lock и время nft/backup.
Не задавайте короткий общий timeout: он может оборвать нормальную операцию.
При завершении посылайте SIGTERM и дайте время на откат; не начинайте с
SIGKILL. Для большого числа доменов используйте планировщик без наложения
запусков и мониторьте задержку.

Если текущий IP всё ещё присутствует в ответе resolver, он сохраняется.
Иначе выбирается один IPv4 из отсортированного набора. Обновления влияют
на новые соединения; активные conntrack-потоки могут использовать старую
ноду до завершения/таймаута. `delete` не является механизмом немедленного
разрыва всех активных соединений.

## Жизненный цикл системы

1. Установить зависимости и скрипт, проверить `--version`.
2. Настроить маршруты и разрешённый FORWARD/обратный трафик в вашем firewall.
3. Создать записи через CLI.
4. Включить приложенный systemd unit для `apply` после reboot.
5. Добавить расписание `refresh`, логирование и ротацию логов.
6. После firewall reload, удаляющего правила, повторить `apply`.
7. При выводе из эксплуатации остановить расписание, выполнить
   `reset --yes`, отключить systemd unit. Архив состояния хранить по вашей
   политике. ip_forward остаётся включённым: его состояние определяет
   общая система, учитывая VPN, контейнеры и другие маршрутизируемые сервисы.

MASQUERADE меняет исходный IP клиента на адрес сервера. Если приложению
нужен исходный IP, требуется другой сетевой дизайн с обратными маршрутами
или подходящий прикладной прокси. OUTPUT-трафик сервера не пробрасывается.
Firewall drop в других цепочках не отменяется этой таблицей.

## Диагностика и контроль

Сохраняйте stdout/stderr и код каждой изменяющей операции. При ошибке
отката журнал содержит путь backup: нужна ручная проверка ядра и TSV.
Следите за свободным диском: каждый backup содержит полный nft ruleset,
автоматического retention нет. Удалять старые backup можно вне активной
операции; актуальную копию сохраняйте до подтверждения работы.

Для production-приёмки проверьте с внешнего клиента TCP, UDP и оба режима,
обратный трафик, DNS-смену, ошибки resolver, конфликт порта, reboot и reload
вашего firewall. Скрипт разработан с проверкой Bash-синтаксиса и тестами
управляющей логики на имитаторах nft/sysctl/DNS; реальная передача пакетов
в данной среде не тестировалась, поскольку nftables здесь отсутствует.

Синтаксис NAT, conntrack и FIB основан на официальном руководстве:
[nftables manpage](https://netfilter.org/projects/nftables/manpage.html).
