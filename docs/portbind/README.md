# portbind: проброс портов на Bash

Linux, Bash 4.4+, nftables, IPv4. Работа через SSH/консоль, без GUI.
Каждая запись задаёт один входной порт, один выходной адрес/порт и протокол:
`tcp`, `udp` или `both`. Один и тот же входной порт нельзя добавить повторно,
даже с другим протоколом или входным адресом.

## Установка

Для Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install nftables libc-bin util-linux coreutils procps gawk
sudo install -m 0755 portbind.sh /usr/local/sbin/portbind
sudo /usr/local/sbin/portbind
```

Скрипт не устанавливает зависимости сам. На других дистрибутивах нужны
`nft`, `getent`, `flock`, `timeout`, `sysctl`, `awk` и обычные coreutils.
Запускайте именно Bash, не `sh`. Обращение к netfilter требует root и
CAP_NET_ADMIN; контейнер без этой capability не подходит.

## Меню

1. Бинд порта: входной адрес, входной порт, выходная нода и порт, протокол.
2. Просмотр: таблица сохранённых перенаправлений.
3. Обновление IP доменов: все домены или один указанный домен.
4. Удаление: по входному порту или полный сброс собственных правил.
5. Выход.

Тип адреса определяется автоматически. Входной адрес `*` означает все
локальные IPv4-адреса сервера. Если указан конкретный входной IP/домен,
правило сопоставляет этот адрес назначения в приходящем пакете. Это должен
быть адрес данного сервера; если перед ним уже есть NAT, укажите адрес,
который пакет имеет **после** того NAT. Домен входа должен разрешаться в
соответствующий IPv4. Выходной адрес — доступная по сети нода.

Не вводите URL (`https://…`), путь или `host:port`: адрес и порт вводятся
раздельно. IPv6 не поддерживается. IDN-домены вводите в punycode.

## Команды

```bash
# TCP: все локальные адреса:8080 → node.example.net:443
sudo portbind add 8080 node.example.net 443 tcp

# UDP: все локальные адреса:5353 → 192.0.2.20:53
sudo portbind add 5353 192.0.2.20 53 udp

# Оба протокола; входной адрес ограничен доменом
sudo portbind add 9000 node.example.net 9001 both entry.example.net

# Оба протокола по умолчанию
sudo portbind add 7000 node.example.net 7001

sudo portbind list
sudo portbind refresh
sudo portbind refresh node.example.net
sudo portbind delete 8080
sudo portbind reset --yes
sudo portbind apply
portbind help
```

Адреса в примерах иллюстративные, замените их своими. Повторный `add`
отклоняется: чтобы заменить запись, сначала удалите старую, затем добавьте
новую. `delete` удаляет всю запись по входному порту, включая оба протокола
для `both`. `reset --yes` очищает записи и собственную NAT-таблицу;
пустая таблица `ip portbind` остаётся. Другие таблицы firewall и таблицы
IP-маршрутизации не сбрасываются.

## DNS и внешний крючок

В конфигурации сохраняются и имя, и текущий IPv4. При добавлении имя
разрешается через системный resolver (`getent ahostsv4`, включая /etc/hosts).
Если IPv4 несколько, используется один: прежний, пока он есть в ответе,
иначе первый после числовой сортировки. Балансировки между IP нет.
Таймаут одного DNS-запроса — 15 секунд. `refresh` обновляет как входные,
так и выходные домены, в том числе все записи с указанным именем.

Готовый крючок для внешнего скрипта:

```bash
/usr/local/sbin/portbind refresh
```

Запускайте от root. Например, в `sudo crontab -e`:

```cron
*/5 * * * * /usr/local/sbin/portbind refresh >> /var/log/portbind-refresh.log 2>&1
```

Либо вызовите `refresh node.example.net` для конкретного домена.
Коды возврата: `0` — успех (включая отсутствие изменений), `1` — ошибка,
`2` — хотя бы один сбой DNS при refresh. При частичном сбое успешно
разрешённые домены обновляются, для остальных остаются прежние адреса.
При ошибке DNS в `add` запись не создаётся. Для лога при постоянной работе
настройте logrotate. Lock ожидается до 30 секунд; открытое меню его не держит.

## Применение, резервные копии и восстановление

Состояние: `/var/lib/portbind/rules.tsv`, 7 колонок без заголовка:
входной порт, протокол, входное имя, входной IPv4, выходное имя,
выходной IPv4, выходной порт. Разделитель — табуляция.
Каталоги имеют права `700`, файлы — `600`, владелец root.

Перед каждым изменением, включая `apply`, создаётся каталог
`/var/lib/portbind/backups/<UTC-время>.<суффикс>` с:

- `rules.tsv`: предыдущая конфигурация;
- `table.nft`: предыдущая собственная таблица, либо пустой файл;
- `full-ruleset.nft`: снимок всех nftables-правил для диагностики;
- `ip_forward`: прежнее значение IPv4 forwarding.

Неудача резервирования останавливает операцию. Перед применением запускается
`nft -c`; замена собственной таблицы идёт одной транзакцией `nft -f`.
Обычная ошибка, SIGINT или SIGTERM после начала изменения вызывают откат
таблицы, конфигурации и ip_forward. Неизменившийся `refresh` резервную копию
не создаёт. Копии автоматически не удаляются: периодически архивируйте или
удаляйте старые вручную.

Восстановление конфигурации из выбранной копии, когда другие экземпляры
скрипта и cron остановлены:

```bash
sudo cp /var/lib/portbind/backups/ИМЯ_КОПИИ/rules.tsv /var/lib/portbind/rules.tsv
sudo chmod 600 /var/lib/portbind/rules.tsv
sudo portbind apply
```

Не загружайте `full-ruleset.nft` поверх текущего firewall без отдельного
плана восстановления: это снимок для администратора. После SIGKILL,
отключения питания или сбоя между обновлением ядра и файла конфигурации
выполните `portbind apply`: он согласует ядро с сохранённым `rules.tsv`.
Атомарность охватывает nftables-транзакцию, а не ядро и файловую систему
одновременно.

## После перезагрузки

Записи сохраняются на диске, но правила ядра требуют повторного применения.
Для systemd есть готовый `portbind.service`:

```bash
sudo install -m 0644 portbind.service /etc/systemd/system/portbind.service
sudo systemctl daemon-reload
sudo systemctl enable --now portbind.service
```

Сервис использует сохранённые IP, не зависит от доступности DNS при старте.
Обновление имён выполняйте через cron. Скрипт включает
`net.ipv4.ip_forward=1` при применении непустой конфигурации. При сбросе он
не выключает forwarding, поскольку его могут использовать другие сервисы.
Firewall reload с `flush ruleset` может удалить таблицу portbind: после
такого reload вызовите `portbind apply` (либо restart этого сервиса).

## Сетевые особенности

Это DNAT + MASQUERADE для входящего сетевого трафика. Благодаря MASQUERADE
ответы выходной ноды возвращаются через сервер проброса; нода видит адрес
этого сервера вместо исходного IP клиента. NAT не создаёт слушающий процесс:
проверяйте подключение с другого компьютера, а не через `localhost` на самом
сервере. Локально исходящие соединения (OUTPUT) скрипт не перенаправляет.

Скрипт не изменяет фильтрующие правила существующего firewall. Если FORWARD
заблокирован UFW/firewalld/iptables/nftables либо сетью провайдера, разрешите
нужное транзитное направление и обратный established/related трафик в вашей
системе firewall. Универсальный `accept` в отдельной таблице не отменяет
`drop` в другой цепочке. Выходная нода должна быть достижима, а сервис должен
слушать нужный порт. Входной порт не должен конфликтовать с нужным локальным
сервисом или существующим DNAT. Имя таблицы `ip portbind` зарезервировано
за этим скриптом; не используйте его для иных правил.

Обновление или удаление влияет на **новые** соединения. Conntrack может
сохранить старое перенаправление для существующих TCP/UDP потоков до их
завершения/таймаута; скрипт не сбрасывает активные соединения.

Для изолированного экземпляра можно задать `PORTBIND_STATE_DIR` (абсолютный
доверенный root-каталог, права 700). Это меняет место состояния, но не имя
таблицы: несколько независимых конфигураций одновременно не поддерживаются.
Для cron и systemd используйте тот же каталог, что при ручном запуске.
