# План развития

Функции добавляются порциями: каждая порция — отдельный коммит, сборка в
GitHub Actions и проверка на реальном сервере перед следующей.
Все операции, которым нужен root, идут через механизм из порции 1.

## Порция 1 — права root для пользователя не root

Проблема: на сервере с пользователем `user` PortBind не работает, потому что
root получается только через `sudo` с паролем входа.

- [x] Настройка сервера «Права root»: `sudo` (пароль входа или отдельный пароль sudo) или `su` (пароль root).
- [x] `su` выполняется через PTY: приложение ждёт приглашение и передаёт пароль root (su не читает пароль из stdin).
- [x] Если sudo требует терминал (`requiretty`), команда автоматически повторяется в PTY.
- [x] Кнопка «Проверить права root» в настройках сервера и на экране PortBind с понятной причиной ошибки
      (нет sudo, не в sudoers, неверный пароль, у root нет пароля и т.д.).
- [x] PortBind и все будущие root-операции используют выбранный способ.
- [x] Способ `sudo su` (по умолчанию): скрипт подаётся root-оболочке через stdin, сначала без пароля (NOPASSWD),
      при запросе — с паролем sudo. Режим `sudo` сам переходит на `sudo su`, если прямой sudo запрещён.

## Порция 2 — ping и порт SSH (экран «Безопасность»)

- [x] Ping: текущее состояние и переключатель `net.ipv4.icmp_echo_ignore_all = 1`
      (и IPv6 `net.ipv6.icmp.echo_ignore_all`, если есть); сохранение в `/etc/sysctl.d/`, чтобы пережить перезагрузку.
- [x] Перенос SSH на другой порт в два этапа, без риска потерять доступ:
  1. добавить новый порт рядом со старым (drop-in в `sshd_config.d` или правка `sshd_config`),
     открыть его в UFW/firewalld, для SELinux — `semanage port`, проверить `sshd -t`,
     перезапустить sshd (учесть `ssh.socket` на Ubuntu 22.10+);
  2. приложение проверяет вход на новом порту;
  3. только после успеха старый порт убирается, порт в приложении обновляется. При ошибке — откат.

## Порция 3 — менеджер UFW

- [ ] Статус, политики по умолчанию, пронумерованный список правил.
- [ ] Добавление правил: allow / deny / reject / limit, порт или диапазон, tcp/udp, источник (IP/подсеть), комментарий.
- [ ] Удаление по номеру, включение и выключение UFW. Перед включением SSH-порт разрешается автоматически, чтобы не потерять доступ.
- [ ] Установка UFW, если его нет; сброс; уровень логирования.
- [ ] Связь с PortBind: подсказки и `ufw route allow` для проброшенных портов (FORWARD по умолчанию DROP).
- [ ] Предупреждение: Docker публикует порты в обход UFW.

## Порция 4 — процессы и службы

- [ ] Список процессов: сортировка по CPU/RAM, поиск, фильтр по пользователю.
- [ ] Детали процесса (команда, пользователь, время запуска, потоки) и сигналы TERM / KILL / HUP (при необходимости от root).
- [ ] Службы systemd: список, статус, start / stop / restart / enable / disable, последние строки журнала.

## Порция 5 — Docker

- [ ] Модуль на сервере: версионируемый скрипт-агент (как portbind) отдаёт данные о Docker
      в машиночитаемом виде (`--format '{{json .}}'`); приложение устанавливает и обновляет его само.
- [ ] Контейнеры: список, start / stop / restart / kill / rm, логи, статистика, inspect, вход в контейнер в терминале.
- [ ] Образы (список, pull, rm, prune), тома и сети (список).
- [ ] Compose-проекты: список, `up -d`, `down`, `pull`, `restart`.
- [ ] Доступ через группу `docker` или root (порция 1); подсказка по установке Docker, если его нет.
